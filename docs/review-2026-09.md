## 1. Вердикт

**Кит в целом.** Зрелый визуальный слой с продуманной токенизацией (ночная рампа, стекло, выпуклость на кромках), API 1:1 с shadcn, чистые типы, контрактные CSS-тесты, которые реально ловят каскадные регрессии. Это сильно выше среднего для 0.x-пакета. Слабые места — не в архитектуре, а в *дрейфе рецептов*: одна и та же идея (ховер, свечение, длительность, подпись на заливке) реализована в 5–10 вариантах, и это заметно глазом, когда контролы стоят рядом.

**DataTable.** Использовать в проектах **можно** — для серверных списков ERP/CRM с пагинацией 25–100 строк, фильтрами в шапке, пинами, ресайзом, выбором и bulk-действиями. Ровно так она уже живёт в eis-frontend. Сдерживают четыре подтверждённых бага (D-01…D-04) и одна архитектурная дыра (D-05 — липкая шапка не работает без высоты скроллера, а высоту задать нечем). После P0 из раздела 7 — без оговорок для этого сценария.

Пока **не подходит** для: spreadsheet-редактирования с клавиатуры (нет grid-навигации, редактирование только двойным кликом); >500 строк на экране в режиме load-more (нет виртуализации и мемоизации строк); controlled `layout` (auto-fit там мёртв, D-02); Next.js App Router или React Router вместе с `urlKey` (D-04 затирает `history.state`); таблицы внутри `<form>` (D-03).

## 3. Подтверждённые дефекты

### 3.1 DataTable

**D-01. Load-more залипает после смены запроса с тем же числом строк.** `askedAt` в `data-table.tsx` запоминает `data.length` на момент запроса и никогда не сбрасывается. Первая страница 50 строк → подгрузка → 100 → пользователь меняет фильтр → хост отдаёт новые 50 строк → `askedAt === data.length` → ни IntersectionObserver, ни кнопка больше не спрашивают. Первая страница почти всегда полная, поэтому сценарий типовой. Probe-тест: `expected "vi.fn()" to be called 2 times, but got 1 times`. **Фикс**: сбрасывать `askedAt` при изменении `query` (сериализованные `filters`/`sort`/`pageSize`) и при уменьшении `data.length`.

**D-02. Auto-fit мёртв при controlled `layout`.** `fitTo` пишет результат в `internal` с `persist: false`, а `layout` при переданном пропе считается как `merge(baseline, controlled)` и `internal` не читает; `onLayoutChange` при fit не вызывается по замыслу. Итог: хост никогда не узнаёт подогнанные ширины, таблица рисует объявленные. Probe-тест: `expected false to be true`. **Фикс**: auto-fit — производное состояние, ему не нужно быть controlled; хранить fitted-ширины во внутреннем overlay и накладывать их поверх controlled для колонок без `sized`. Хост остаётся источником правды для пользовательских правок.

**D-03. Таблица внутри `<form>` отправляет форму.** 14 внутренних `<Button>` (пагинация, Apply/Reset фильтра, Reset колонок, bulk-бар, load-more, retry) без `type="button"`, а `Button` не задаёт `type`. Probe-тест: клик по «Next page» вызвал `onSubmit`. **Фикс (P0, не ломающий)**: `type="button"` во всех внутренних использованиях. **К 1.0**: обсудить дефолт `type="button"` в `Button` при `!asChild` — это расходится с shadcn/native, но убирает целый класс ошибок; вынести в changelog.

**D-04. `useTableQuery` затирает `history.state` и пишет URL при монтировании.** `window.history.replaceState(null, '', next)` уничтожает state, на который опираются Next.js App Router (`__NA`, tree) и React Router (`usr`/`key`/`idx`): кнопка «назад» и `navigate(-1)` начинают вести себя непредсказуемо. Плюс `encode` всегда пишет `size`, поэтому URL меняется сразу на mount без единого действия (в playground: `?orders.sort=-date&orders.size=10`). **Фикс**: `replaceState(window.history.state, …)`; не писать параметры, равные `initial`; клампить `page ≥ 1`; дать `serialize/deserialize` для `filters` — `JSON.stringify` даёт длинные URL и падает на несериализуемых `custom`-значениях.

**D-05. `stickyHeader` (по умолчанию `true`) не работает без высоты скроллера.** `.mz-dt__scroller` — `overflow: auto` без `max-height`, sticky считается относительно него, а он растёт по контенту и никогда не скроллится. Пропа для высоты нет, `.mz-dt` не умеет заполнять родителя. **Фикс**: `maxHeight?: number | string`, `height?`, и модификатор `fill` (`.mz-dt { height: 100% }`, `.mz-dt__scroller { flex: 1; min-height: 0 }`).

**D-06. Дублирующиеся `id` в date-range фильтре.** `id="mz-dt-from"` / `"mz-dt-to"` захардкожены в `column-filter.tsx`; две таблицы на странице — два одинаковых id, `htmlFor` ведёт не туда. **Фикс**: `React.useId()`.

**D-07. `ColumnFilterDef` number-range `unit` — мёртвый проп.** Объявлен в `types.ts`, не читается ни в `FilterBody`, ни в `describeFilter`. **Фикс**: суффикс в инпутах и в тексте чипа, либо убрать из типа.

**D-08. `headerTitle` работает только у несортируемых колонок.** У сортируемых `title` занят `labels.sortBy(label)`. **Фикс**: `title={column.headerTitle ?? labels.sortBy(label)}`, подсказку про Shift перенести в `aria-description`.

**D-09. `aria-sort="none"` на всех `th`, включая несортируемые.** По ARIA `aria-sort` означает «колонку можно сортировать». **Фикс**: атрибут только при `column.sortable`.

**D-10. Заголовок колонки с `align: 'right'` и фильтром прижат влево.** `.mz-dt__filter { margin-left: auto }` выталкивает подпись к левому краю, значения при этом справа (видно на «Total» в playground). **Фикс**: для `data-align="right"` ставить фильтр перед подписью (`order: -1; margin: 0 auto 0 0`).

**D-11. Ошибка сохранения в `CellEditor` невидима и непереводима.** Текстовый редактор кладёт сообщение только в `title` и `aria-invalid`; строка «Could not save» не в `labels`; select-редактор при отказе молча откатывает значение и остаётся открытым без сообщения. **Фикс**: `labels.saveFailed`, инлайн-сообщение с `aria-live`, единое поведение обоих редакторов.

**D-12. Чипы фильтров не локализованы.** `describeFilter` печатает `date-range` сырыми ISO-строками, `number-range` — без `toLocaleString(locale)` и без `unit`; в пагинации `from–to` не форматируются, а `total` форматируется — «1–25 of 13 659». **Фикс**: `Intl.DateTimeFormat(locale)` и `toLocaleString(locale)` везде.

**D-13. Семантика select/boolean фильтров.** `select` с `multiple: false` рисует чекбоксы, ведущие себя как радио; boolean — чекбоксы внутри `role="radiogroup"`. **Фикс**: `RadioGroup` из кита в обоих случаях.

### 3.2 Визуальный слой

**V-01. Белая подпись на тоновых заливках в тёмной теме не проходит контраст.** Всё, что «залито тоном» (primary/destructive кнопка, toggle on, active tab, checked switch/checkbox, badge solid, sidebar active, calendar selected, tooltip), красит текст `#fff` литералом; `--mz-primary-fg` объявлен и нигде не используется.

| Тон (dark) | `#fff` | ink `#0a0a12` | Тон (light) | `#fff` | ink |
|---|---|---|---|---|---|
| primary | 3.04 | 6.48 | primary | 5.25 | 3.76 |
| accent/success | **1.92** | 10.26 | accent/success | **2.82** | 6.98 |
| danger | **2.84** | 6.95 | danger | 4.17 | 4.73 |
| warning | **1.67** | 11.81 | warning | **2.94** | 6.71 |
| info | **2.14** | 9.20 | info | 3.48 | 5.67 |

AA для 14px/500 — 4.5:1. В dark ни один тон не проходит с белым; accent/warning/info — на уровне «не читается» (см. кадр `btn-tones-dark`). **Фикс**: токен `--mz-tone-fg` (см. 6.4).

**V-02. Двойное кольцо фокуса у `SelectTrigger`.** Он носит `mz-focusable` (outline из `base.css`) и одновременно свой box-shadow-glow из `overlays.css`; `outline: none` в его собственном правиле проигрывает по специфичности `.mz-focusable:focus-visible`. Input/Textarea рисуют только glow. В одной форме два разных фокуса (кадры `input-focus` / `select-focus`, в light ещё заметнее).

**V-03. Ховер кнопки ≠ ховер тогла (пример из запроса подтверждён).** Три расхождения между контролами, стоящими рядом:
- `Button primary` на ховере темнеет **и растёт** (`scale 1.02`); `Toggle` в состоянии on только темнеет; scale у тогла есть лишь на press.
- `Toggle` default (прозрачный в покое) на ховере получает полную поднятую грань `--mz-face-hover` (9% белого) + `--mz-border-plain` (24%) — визуально это `Button secondary` в покое. `Button ghost` (тоже прозрачный в покое) на ховере получает 6% ink-wash + `--mz-border` (13%). Два прозрачных контрола зажигаются по-разному (кадры `tgl-bold-hover` / `btn-ghost-hover`).
- `Switch` в состоянии off **не имеет ховера вообще** (кадры `switch-idle` / `switch-unchecked-hover` идентичны), тогда как checkbox/radio получают тоновый рим.
- `Input` на ховере — нейтральный рим 24% от текста; `SelectTrigger` — тоновый рим 45% + осветление грани. Один ряд формы, два ответа на курсор.

**V-04. Десять вариантов тонового свечения** для одной идеи «выпуклая заливка светится вниз»: кнопка `0 3px 10px -4px .4`, checkbox/radio `0 3px 10px -5px .7`, switch `0 4px 12px -6px .75`, toggle on / sidebar active `0 6px 16px -10px .8`, badge `0 6px 16px -8px .7`, tabs `0 8px 24px -10px .6`, calendar `0 6px 18px -8px .7`, tooltip `0 10px 30px -10px .6`, card `0 24px 60px -28px .55`, alert `0 10px 30px -20px .8`.

**V-05. Дрейф мелких констант.** Ghost-wash на ховере: 6 / 7 / 8 / 10 / 12 % в разных иконочных кнопках. Длительности: 0.14 / 0.15 / 0.16 / 0.2 / 0.28 s. Press-scale: `.98` (кнопки, switch, toggle), `.94` (checkbox, radio), `1.06` (slider thumb — растёт вместо сжатия).

**V-06. `Table` и `DataTable` — две разные шапки.** `.mz-table__th`: 12px, `--mz-label-font/tracking/transform`, фон `--mz-well`, padding 10/12. `.mz-dt__th`: 14px, наследуемый шрифт, фон `--mz-glass-well`, высота строки. Две таблицы на одной странице выглядят как два кита. Ховер/selected строк тоже разные (3.5% wash vs color-mix 4.5%; `rgba(tone,.12)` vs `color-mix 12% primary`).

**V-07. Воронка фильтра в каждой шапке — шум.** Шесть одинаковых иконок в ряду (кадр `dt-full`). Норма для плотных таблиц — показывать триггер на hover/focus-within и всегда — когда фильтр активен.

**V-08. Рамка DataTable внутри Card.** `.mz-dt__scroller` всегда с бордером, радиусом и `--mz-shadow-2`; внутри карточки получается двойная рамка (кадр `page-top`). Нужен `frame="plain"`.

**V-09. Sheet без внутреннего паддинга контента.** Header/footer имеют padding 20, тело — нет; Dialog даёт `padding: 22px` всему контенту. Контент шита упирается в край.

**V-10. Двадцать захардкоженных `--mz-primary-rgb` в компонентных стилях** (chips, `__count`, sidebar badge, sort-icon active, resizer, card hover, accordion hover, sub-button active): эти места не следуют `tone`. `.mz-dt`, `.mz-card`, `.mz-accordion-trigger`, `.mz-sidebar` не входят в список тоновых корней в `base.css`.

**V-11. Неиспользуемые токены.** `--mz-bg-rgb`, `--mz-surface-rgb`, `--mz-elevated-rgb`, `--mz-primary-fg`, `--mz-primary-glow`, `--mz-primary-soft`, `--mz-radius-xl` (плюс намеренные алиасы `--mz-face-fill*`). Либо задействовать, либо вычистить из публичного `tokens.css`.

**V-12. Мелочи.** `.mz-badge` с `overflow: hidden; white-space: nowrap` без `text-overflow` режет длинный текст. Иконка sort в покое `stroke-width: 3` на 16px читается тяжелее активной стрелки.

### 3.3 Остальной кит и пакет

**K-01. Размерная сетка неполная.** `SelectTrigger` — только `sm|md`, в ряду с `Input inputSize="lg"` (48px) и `Button lg` селект не встаёт. `RadioGroupItem` без `size` (Checkbox/Switch — с). `Textarea` без размера.

**K-02. `Dialog` без `size`.** `max-width: 32rem` фиксирован, любой другой — через className. Нужны `sm|md|lg|xl|full`.

**K-03. `Alert` всегда `role="alert"`.** Статичный алерт на странице озвучивается скринридером при каждом рендере. Нужен `live?: boolean` / переопределение `role` (у shadcn та же проблема).

**K-04. `SidebarProvider` перехватывает Ctrl/⌘+B глобально и без отключения.** Конфликт с закладками Firefox и «жирным» в редакторах. Нужен `shortcut?: string | null`.

**K-05. `ToggleGroupItem` игнорирует собственный `tone`** (variant/size переопределяются, tone — нет).

**K-06. `Progress` без `indeterminate`; `AvatarGroup` без `max` («+3»).**

**K-07. Глобальное `disabled { pointer-events: none }`** отключает tooltip на disabled-кнопке (частая жалоба к shadcn). Рассмотреть `cursor: not-allowed` без `pointer-events` там, где это безопасно.

**K-08. Peer `react ^19`** — осознанно (ref как проп), но исключает React-18 хосты. Зафиксировать в README как ограничение, не как случайность.

**K-09. История и релизы.** 10 коммитов, из них 6 — «bump x.y.z»; CHANGELOG нет; версии 0.2.x→0.3.7 с реальными изменениями API без записи. Нужны CHANGELOG и conventional commits.

**K-10. Тесты без браузерного раннера.** FIXES честно фиксирует: заморозка от ResizeObserver и redistribute-on-hide защищены только комментариями. Playwright CT или `vitest --browser` для `data-table.test.tsx` закроют это.

**K-11. Отсутствующие композиты, которые хосты собирают руками**: `DatePicker` / `DateRangePicker` (Calendar уже есть; date-range фильтр таблицы использует нативный `<input type="date">` вместо него), `Combobox` / `MultiSelect` с async-опциями (ровно то, что eis-frontend протаскивал через `custom`-фильтр), `Command` (⌘K), `Collapsible`, `ContextMenu` (правый клик по строке), `NumberInput`, `Empty`, `Kbd`.

**K-12. `background-attachment: fixed` на `.mz-root` и `.mz-sidebar-layout`** — дорогой для композитора паттерн рядом с `backdrop-filter`, на iOS игнорируется. Дешевле — фиксированный псевдоэлемент-слой `::before { position: fixed }`.

## 4. DataTable: детальное ревью

### 4.1 Что сделано хорошо

- **Модель «одно действие — один запрос»**: `DataTableQuery` как единственный выход, `setFilter`/`toggleSort` чистые, `page` сбрасывается сам. Это правильная граница для серверных данных, и её легко тестировать.
- **Ресайз без ре-рендера**: ширина пишется в CSS-переменную на корне, `<col>` перерисовывается, состояние коммитится на pointerup. Sticky-offsets выражены через `calc(var(--mz-dt-w-*))`, поэтому пины не разъезжаются во время drag.
- **Auto-fit детерминирован**: считается от объявленных ширин, история подгонок ломает 2-цикл со скроллбаром. Хорошая защита от дрейфа.
- **Идентичность состояния из наблюдателей** — урок из FIXES усвоен: `setScrolled` bail-out, `onLoadMore` через ref, `useColumnLayout` персистит вне updater'а.
- **Column manager** группирует так, как таблица красит (pinned → loose → pinned), даёт клавиатурные стрелки и не начинает drag с кнопок.
- **Пагинация без `total`** сделана честно: «следующая есть, если страница полная».
- **Локализация**: `labels` + бандлы `ru`/`en` с тестом на полноту.
- **Строковые хуки** `rowClassName`/`rowProps` с правильным приоритетом атрибутов таблицы.

### 4.2 Пробелы для реальных проектов

**G-01. Клавиатура.** Кликабельная строка (`onRowClick`) не фокусируется и не активируется Enter; редактирование — только двойной клик, ячейки не фокусируемы; нет grid-навигации (`role="grid"`, roving focus). Для ERP-таблицы это заметный разрыв с ожиданиями.

**G-02. `onRowClick` срабатывает от кликов по интерактивным потомкам** (ссылка, кнопка, badge-меню в ячейке) — хост обязан сам `stopPropagation`. Норма: игнорировать клики из `a, button, input, select, textarea, [role=button], [role=menuitem]`.

**G-03. Раскрытие строк только uncontrolled.** Нет `expanded`/`onExpandedChange`/`defaultExpanded`, «раскрыть все», `expandOnRowClick`.

**G-04. Глобальный поиск не входит в `query`.** Инпут в toolbar (как в демо) живёт отдельно, не попадает в URL через `useTableQuery`, не сбрасывает `page`. Правило «одно действие — один запрос» здесь нарушается.

**G-05. Нет стилевых хуков на уровне колонки** (`className`/`headerClassName`/`cellClassName`), нет `footer`/summary-строки (итоги — типовая потребность ERP), нет `sortDescFirst` для чисел/дат.

**G-06. Производительность на больших списках.** Строки не мемоизированы, любое изменение состояния (выбор, раскрытие, редактирование) перерисовывает все ячейки; в load-more список растёт без предела. Для пагинации 100×10 — нормально; для 1000+ строк — нет.

**G-07. Persist без версии схемы.** `ColumnLayout` в localStorage без `v`; смена формы в будущем релизе ломает сохранённое. `sized` навсегда исключает колонку из auto-fit, единственный выход — полный Reset.

**G-08. Фильтры.** `text` без оператора (`contains`/`equals`/`startsWith` нужны бэкендам чаще, чем кажется); `select` без поиска по опциям и без «выбрать все»; `date-range` — нативный `<input type="date">` вместо `Calendar` (чужой вид, чужая локаль); чипы `select` с десятком значений не усекаются («+N»).

**G-09. A11y состояний.** Нет `aria-busy` на таблице при `loading`, нет `aria-rowcount`, счётчик «Selected: N» не в `aria-live`.

**G-10. ColumnManager для 30+ колонок** — без поиска и «показать/скрыть все»; HTML5 DnD не работает на touch (стрелки есть).

**G-11. Контракт load-more неполный.** `onLoadMore()` без аргументов, `query.page` таблица не инкрементирует — хост должен вести счётчик сам; README это не объясняет.

**G-12. `cssSafe`** схлопывает `a.b` и `a_b` в одну переменную.

**G-13. RTL**: пины на физических `left/right`.

**G-14. Skeleton** — одна ячейка на всю ширину, не повторяет колонки.

### 6.2 Целевая модель: три глагола

Каждый контрол в покое принадлежит одной из трёх поверхностей, и ховер/пресс — свойство поверхности, а не компонента.

1. **Filled** (primary/destructive button, toggle on, tab active, switch/checkbox/radio on, sidebar active, calendar selected, badge solid): hover — `--mz-fill-hover`; press — `--mz-fill-press`. **Scale**: только у самостоятельных кнопок (`.mz-btn`), никогда у элементов групп (segmented/joined/tabs), где рост заезжает на соседа. Toggle вне группы — с scale, как кнопка; внутри группы — без. Это снимает расхождение из запроса и сохраняет причину, по которой группы не масштабируются.
2. **Raised neutral** (secondary button, toggle outline, select trigger, joined items, calendar nav, toast action): hover — `--mz-face-hover`, рим не меняется. У `SelectTrigger` тоновый рим на ховере убрать — тон остаётся сигналом фокуса/открытия, как у `Input`. Scale — по тому же правилу, что выше.
3. **Flat** (ghost button, toggle default, segmented item, menubar/navmenu trigger, sidebar item, все иконочные кнопки, sort/filter в шапке, calendar day): hover — один токен `--mz-wash-hover`, press — `--mz-wash-press`, рим — `--mz-border` (hairline) там, где у контрола есть форма (кнопка), и без рима у элементов списков. `Toggle default` перестаёт превращаться в secondary-кнопку и зажигается как ghost.

Отдельно: **Switch off получает ховер** — тоновый рим 50%, как checkbox/radio (это одна семья). **Slider thumb** — press `scale .98`? Нет: у ползунка рост под курсором оправдан (его тянут), оставить, но задокументировать как исключение вместе с outline-кнопкой.

### 6.3 Фокус

Одна система на весь кит: `.mz-focusable` → `outline`. Поля (`Input`, `Textarea`, `SelectTrigger`) — вторая, единая для них система: тоновый бордер + мягкий glow, **без** outline. Для этого достаточно убрать `mz-focusable` у `SelectTrigger` (класс добавляется в `select.tsx`) и оставить его `:focus-visible`-правило. Проверить после правки кадр `select-focus` в обеих темах.

## Приложение A. Probe-тесты (vitest, happy-dom)

Три из четырёх упали на текущем коде — это и есть подтверждение D-01, D-02, D-03. Четвёртый (render-loop при inline `columns` + controlled `layout`) прошёл: петли нет, потому что fit пишет во внутреннее состояние таблицы, а не хоста.

```tsx
// D-01
it('asks again for the new result set', async () => {
  const onLoadMore = vi.fn()
  const q1 = { ...emptyQuery, pageSize: 2 }
  const { rerender } = render(<DataTable columns={columns} data={page('a')} rowKey={(r) => r.id}
    total={100} query={q1} onQueryChange={vi.fn()} onLoadMore={onLoadMore} autoLoadMore={false} />)

    total={100} query={q2} onQueryChange={vi.fn()} onLoadMore={onLoadMore} autoLoadMore={false} />)
  await userEvent.click(screen.getByRole('button', { name: 'Load more' }))

})

// D-02
it('fitTo reaches the host when layout is controlled', () => {
  const onLayoutChange = vi.fn()
  const { result } = renderHook(() => useColumnLayout({
    columns: [{ id: 'a', header: 'A', width: 100 }, { id: 'b', header: 'B', width: 100 }],
```

## Приложение B. Как снимались состояния

Headless Chrome (`/opt/google/chrome/chrome --headless=new --use-angle=swiftshader --remote-debugging-port`) + CDP из Node 22 (встроенный `WebSocket`): `Page.navigate` → `Runtime.evaluate` для координат → `Input.dispatchMouseEvent mouseMoved` / `el.focus()` → `Page.captureScreenshot` с `clip` в координатах документа. `background-attachment: fixed` на время съёмки отключался.
